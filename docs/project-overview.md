# 프로젝트 개요

## 목적과 접근 방식

oms-wms-lab은 주문(OMS)과 창고(WMS)가 만나는 지점의 문제를 다루는 프로젝트다. 이미 동작하는 프로젝트에 합류해 코드를 파악하고, 기존 기능을 유지하면서 문제를 해결하는 경험을 재현한다.

출발점인 base는 AI(Claude)가 작성했다. 주문부터 결제·출고·취소까지 동작하는 흐름에 의도적으로 한계를 남겨 두고, 이후 버그·장애·신규 요구를 단계별로 해결한다. 처음부터 전체를 설계하는 대신 기존 구조의 한계를 재현하고 변경의 효과와 부작용을 확인하는 데 초점을 둔다.

base는 얇은 CRUD에 그치지 않도록 전체 업무 흐름을 포함하되, 주문과 재고 처리에 집중할 수 있는 범위로 제한했다. 코드를 일부러 난해하게 만들기보다 일관된 계층 구조와 단순한 구현을 출발점으로 삼았다.

## 단계 구성

기존 동작을 파악하는 온보딩으로 시작해 버그·장애를 해결하고, 이후 새로운 업무 요구를 반영한다. 아래는 단계별 과제이며, 완료 여부와 실제 해결 내용은 [README의 단계별 기록](../README.md#단계별-기록)에서 확인할 수 있다.

| 단계 | 유형 | 증상 또는 요구 |
|---|---|---|
| 0 | 온보딩 | 애플리케이션을 실행하고 주문·결제·출고·취소 흐름을 파악한다. |
| 1 | 버그 | 주문이 동시에 몰리면 재고가 음수로 떨어진다. |
| 2 | 버그 | 결제하지 않고 이탈한 주문 때문에 실물재고가 남아 있어도 신규 주문이 품절로 거절된다. |
| 3 | 장애 | 출고 처리가 느려지거나 실패하면 결제 완료까지 영향을 받는다. |
| 4 | 신규 요구 | 두 번째 창고를 추가하고, 한 창고의 재고로 부족한 주문은 여러 창고에서 나누어 출고한다. |
| 5 | 신규 요구 | 피킹이 진행 중인 주문에서도 일부 상품을 취소할 수 있도록 한다. |
| 6 | 신규 요구 | 반품 접수 후 검수 결과에 따라 재입고와 부분환불을 처리한다. |

## base의 기능 범위

아래는 프로젝트 출발점의 범위다. 이후 변경된 동작과 검증 결과는 [README의 단계별 기록](../README.md#단계별-기록)과 연결된 이슈·PR에서 확인할 수 있다.

| 영역 | 내용 |
|---|---|
| 상품·재고 | SKU, 가격, 창고 1개, SKU별 재고 수량 |
| 주문 | 여러 라인을 가진 주문 생성, 상품금액·배송비·쿠폰 할인에 따른 금액 계산, 주문 상태 |
| 결제 | 가짜 PG를 통한 승인·취소 |
| 출고 | 결제 완료 시 출고지시 생성, 피킹·패킹·출고완료 상태 변경 |
| 취소 | 출고 전 주문의 전체 취소와 환불 |
| 조회 | 주문·재고·출고 조회 API |

UI 없이 API와 테스트로 동작을 확인한다. 회원·인증, 상품 전시, 실제 PG 연동, 입고·로케이션·피킹 경로는 범위에 포함하지 않는다. 고객은 ID 값으로만 표현한다.

## base의 구조와 테스트

Controller → Service → Repository 계층으로 구성하며, 업무 로직은 서비스에 두고 엔티티는 주로 데이터를 보관한다. 초기 테스트는 정상 경로를 중심으로 작성했다.

이 구조와 테스트 범위는 출발점에 대한 설명이다. 현재 구현의 품질이나 안전성을 보장하는 근거는 각 변경의 코드와 재현·검증 결과다.

## 기술 구성

| 구분 | 구성 |
|---|---|
| 언어·프레임워크 | Java 25, Spring Boot 4.1.1 |
| 영속성·스키마 관리 | JPA, MySQL, Flyway |
| 빌드·코드 작성 지원 | Gradle 단일 모듈, Lombok |
| 테스트·로컬 실행 DB | Testcontainers 기반 MySQL |

동시성 문제를 실제 사용할 DB의 동작에 가깝게 검증하기 위해 MySQL을 사용한다. H2로 대체하지 않고 테스트와 로컬 실행에서도 MySQL 컨테이너를 사용해 락 동작 차이에 따른 재현 결과의 차이를 줄인다.

## 작성 주체와 변경 근거

base 코드는 AI가 작성한 출발점이며 사용자가 구현한 결과물과 구분한다. 이후 증상 재현, 원인 진단과 해법 결정은 사용자가 수행한다. 코드는 직접 작성하거나 구체적으로 지시해 AI의 도움을 받으며, AI가 작성한 변경에는 커밋의 공동 작성자 표시를 남긴다.

실제 변경의 원인·선택한 해법·버린 대안·남은 위험·검증 결과는 이슈와 PR을 기준으로 확인한다. 프로젝트의 실행 방법과 API, 업무 규칙은 [README](../README.md)에 정리한다.
