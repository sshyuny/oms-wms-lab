이슈: [#6 — 출고 처리가 느려지거나 실패하면 결제 완료까지 영향을 받음](https://github.com/sshyuny/oms-wms-lab/issues/6)

목표는 출고 처리 지연이나 실패가 발생해도 결제가 정상적으로 완료되도록 하는 것이다.

## 1. 처리 흐름과 범위 정하기

- [x] 결제 요청 안에서 끝낼 일과 이후에 처리할 일을 구분한다.
- [x] 전달할 이벤트의 의미와 내용을 정한다.
- [x] 이번 작업에 포함할 범위를 정한다.

결정한 내용:

- 결제 요청에서는 결제 저장·주문 상태 변경·아웃박스 기록까지 처리하고, 출고 생성은 이후 릴레이를 통해 처리한다.
- 이벤트는 “이 주문의 출고를 생성해 달라”는 요청이며, 핵심 내용은 주문 ID다. 이벤트 식별자 등 처리용 정보는 2단계에서 정한다.
- 이번 범위는 결제 시 출고 생성 직접 호출을 이벤트 처리로 분리하는 것이다.
- 출고 생성 요청의 실패·중복·재시도 대응은 5단계에서 다룬다.

## 2. 아웃박스 테이블 구조 짜기

- [x] 이벤트 식별자, 내용, 처리 상태, 생성 시각 등 필요한 항목을 정한다.
- [ ] 실패·재시도에 필요한 정보를 정한다。（5단계에서 검토）
- [x] 결정한 구조를 스키마와 코드에 반영한다.

결정한 내용:

- 여러 종류의 이벤트를 담을 수 있는 공용 `outbox_event` 테이블을 사용한다.
- `id`를 메시지 고유 ID로 사용하며, 재시도 시에도 같은 ID를 전달한다.
- 이번 이벤트는 `event_type = SHIPMENT_CREATION_REQUESTED`, `payload = {"orderId": 123}` 형태로 담는다.
- 상태는 처리 대기 `PENDING`과 처리 완료 `PROCESSED`로 시작한다. 실패한 이벤트는 `PENDING`으로 남겨 재시도한다.
- 재시도 횟수·실패 이유·다음 시도 시각 등 추가 컬럼은 5단계에서 정책과 함께 검토한다.
- 마이그레이션·엔티티·리포지토리 작성 완료. `./gradlew test`로 MySQL에서 V1 → V2 적용 성공과 기존 테스트 16개 통과를 확인했다. 아웃박스 엔티티의 저장·조회는 아직 검증하지 않았다.

합의한 기본 스키마:

```sql
CREATE TABLE outbox_event (
    id           BIGINT AUTO_INCREMENT PRIMARY KEY,
    event_type   VARCHAR(100) NOT NULL,
    payload      JSON NOT NULL,
    status       VARCHAR(20) NOT NULL DEFAULT 'PENDING',
    created_at   DATETIME(6) NOT NULL,
    processed_at DATETIME(6) NULL,
    INDEX idx_outbox_event_status_id (status, id)
);
```

## 3. 결제 시 아웃박스에 기록하도록 변경하기

- [x] 결제 저장·주문 상태 변경·아웃박스 기록을 같은 DB 트랜잭션으로 묶는다.
- [x] 결제 흐름에서 기존 출고 생성 직접 호출을 제거한다.

구현·검증 기록:

- `PaymentService.approve()`에서 출고 직접 호출을 제거하고 `ShipmentEventRepository.publishShipmentCreation(orderId)`를 호출한다.
- `ShipmentEventRepository`는 `SHIPMENT_CREATION_REQUESTED` 이벤트를 만들고, `ObjectMapper`로 `{"orderId": 123}` 형태의 payload를 직렬화해 아웃박스에 저장한다. mapper는 `private final`로 선언했다.
- 이벤트 저장은 기본 트랜잭션 전파 방식으로 결제 트랜잭션에 참여한다. 결제 저장·주문 상태 변경·아웃박스 기록이 함께 커밋되거나 롤백되는 구조다.
- 코드 리뷰와 `./gradlew compileJava` 통과를 확인했다. 이후 mapper의 `private final` 변경은 코드로 확인했으며, 컴파일을 다시 실행하지 않았다.
- 실제 JSON 저장·조회와 트랜잭션 롤백은 아직 검증하지 않았다. 3단계 변경 후 전체 테스트도 아직 실행하지 않았다.
- 릴레이 구현 전이므로 결제 후 출고가 생성되지 않는 상태다.
